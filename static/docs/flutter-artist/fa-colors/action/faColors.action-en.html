Interaction & Feedback Language (Action Namespace)

While Selection is dedicated to data rows, the Action Namespace is the soul of independent interactive components. This set is optimized for small surfaces with high interaction density, helping users intuitively identify clickable and command-driven elements.

1. Scope of Application

Whenever you create "clickable" elements that are not table rows, think of Action tokens. Specifically:

  • Navigation Elements: Buttons (Primary, Secondary, Ghost).
  • Status & Label Elements: Chips, Badges, Tags.
  • Quick Selection: Filters or toggle switches.

2. The "Interactive Trio" Philosophy (Surface - Text - Border)

To ensure buttons remain sharp and prominent on any background, the Action Namespace strictly follows the coordination between:

  • Background (Surface): faColors.action.fill.xxx defines the color for the button or chip body.
  • Content (Text/Icon): faColors.action.ink.xxx ensures text and icons maintain perfect contrast against the button surface.
  • Stroke (Border): faColors.action.border.xxx is essential for Outlined Buttons or Chips requiring subtle separation.

3. Multi-Environment Adaptability

One of the core strengths of the Action set is its ability to "survive" on various surfaces. These Buttons and Chips can be safely placed on:

  • Standard Surfaces: Main content areas.
  • Control Bars: Inside AppBars or ToolBars.
  • Navigation Bars: Where Actions can function as Menu Items.
NAVIGATION NOTE: When Buttons or Chips serve as primary Menu Items on a navigation bar, you have a flexible choice: Use faColors.action.xxx for independent interactions, or faColors.nav.xxx to leverage specialized Active/Inactive states for navigation flows.

4. The "No-Mix" Coordination Rule

Similar to Selection, you should not use standard text colors (faColors.ink.primary) on a Primary Action button. Always use its designated partner, faColors.action.ink.primary, to ensure FlutterArtist's contrast calculation algorithms perform at their best.
