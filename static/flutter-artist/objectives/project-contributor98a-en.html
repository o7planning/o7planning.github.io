Server-Side Procedures with BlockBackendAction

This example explores BlockBackendAction, a powerful mechanism designed to execute server-side procedures and synchronize the results with the local application state.

  • Executing Complex Operations: BackendAction is ideal for operations that impact multiple resources or execute database procedures (e.g., adding multiple contributors to a project) where the final data structure might not be a simple single-item update.
  • Automated State Refresh: It highlights the AfterBlockBackendAction.query configuration, which ensures the Block automatically re-triggers its query after a successful server operation. This guarantees the UI reflects the most up-to-date data from the database.
  • Event Emission & Observability: BackendAction can emit events both internally and across the Shelf. This allows other Blocks or Scalars to listen and react (refresh) to the changes, maintaining a fully synchronized reactive system.

Technical Focus: Managing server-side procedure lifecycles and utilizing automatic re-querying logic for synchronized data states.

Refer to the initDefaultConfig implementation in Related Documentation to see the auto-query configuration.
