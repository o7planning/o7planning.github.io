faColors.input

In the Surface - Ink - Stroke architecture, the Input namespace provides a dedicated system for form fields and text areas. By splitting interactive variables into strict fill and stroke sub-namespaces, FlutterArtist ensures that input components maintain unambiguous state feedback across dense enterprise forms.

1. Architecture Breakdown

The input layout system is divided into two operational layers to handle various lifecycle states:

Sub-Namespace Token Name Target InputDecoration Property
.fill (Surfaces) faColors.input.fill.enabled fillColor (When enabled: true)
faColors.input.fill.disabled fillColor (When enabled: false)
.stroke (Boundaries) faColors.input.stroke.enabled enabledBorder
faColors.input.stroke.disabled disabledBorder
faColors.input.stroke.focused focusedBorder
faColors.input.stroke.error errorBorder
faColors.input.stroke.focusedError focusedErrorBorder

2. Typography & Ink Alignment

To eliminate structural redundancy, the input namespace deliberately delegates all typography behaviors to the global faColors.ink system. When configuring input text fields, developers must explicitly map textual layers according to the following contrast rules:

  • Input Value text: Driven by faColors.ink.primary to maintain definitive reading contrast against the active container fill.
  • Hint & Placeholder text: Driven by faColors.ink.muted to represent an inactive, low-contrast suggestion state.
  • Floating Label text: Driven by faColors.ink.primary during focus transitions, and faColors.ink.secondary when resting idle.
  • Validation Helper text: Driven by faColors.ink.danger to visually align with active semantic error boundaries.

3. The Core Design Doctrines

  • The Neutral Canvas Rule: Fill tokens are tied directly to calculated neutral containers. Never inject primary or high-saturation hues into the fill sub-namespace, preventing visual fatigue during extended data-entry sessions.
  • State Persistence: When a field encounters an error, the stroke.focusedError token guarantees that the boundary color remains structural and urgent while the user is actively correcting the fault.
  • Structural Weight Shifts: Boundary tokens are designed to scale gracefully. Idle and locked states (enabled, disabled, error) utilize a clean 1.0 logical pixel layout, while active states (focused, focusedError) expand to 2.0 logical pixels to guide the user's attention.
Theme Reactivity Note: Every token inside the faColors.input scope is context-aware. During a Dark Theme transition, opacity modifiers and container elevations adjust seamlessly within the FaColorGraph engine to protect text contrast.
